# Replication material

**Complements in the Queue: What Re-Studying Recovers, and What Only a Joint
Interconnection Study Can**
Hugo Farajallah, Independent Research — <research@hugofara.net>
ORCID [0009-0001-0769-4434](https://orcid.org/0009-0001-0769-4434)

This archive holds the joint-allocation engine, every experiment script, and the
numerical outputs behind each reported result. The manuscript itself is in
`docs/papers/latex/`, source and compiled.

## Layout

| Path | Contents |
|---|---|
| `src/allocation/` | The allocation engine: GLDF surrogate, MILP certifier, AC oracles, baselines |
| `src/gridsynth/` | The OpenDSS→pandapower importer every feeder arrives through, and the LV conductor catalogue the reinforcement lever prices against |
| `experiments/` | 103 numbered scripts, one per experiment; each is runnable standalone |
| `outputs/` | The results those scripts wrote, indexed by [`outputs/MANIFEST.md`](outputs/MANIFEST.md) |
| `outputs/logs/` | Console logs of the original runs; the provenance behind much of that index |
| `data/interconnection/` | The empirical interconnection-request size distribution behind Appendix A |
| `docs/papers/` | The manuscript, the pre-registration, and the figure sources |
| `docs/logs/` | Per-feeder laboratory notebooks: how each result was obtained, what was superseded, what was retracted |
| `docs/joint-allocation-scope.md` | The engine build log, M0–M21 |
| `test/` | Unit tests |
| `tools/` | `build_manifest.py`, which regenerates the output manifest |

The experiments carrying this paper are 91, 101, 103, 107, 109, 110 and 125–132.
`129_outside_relief.py` is the enumeration behind Section 5.4;
`131_ckt24_yearly.py` the year-round check behind Section 5.10;
`132_voltvar_reference_cell.py` the Volt/VAr re-run behind Section 5.11.
Appendix A's arrival-order lottery is experiments 71–77, logged in
`docs/logs/arrival-order.md`.

Script numbering is the original laboratory numbering and is not contiguous:
experiments belonging to this project's other research lines have been removed
from this archive, and their numbers are simply absent.

## Running

Python 3.12. Dependencies are pinned in `uv.lock`; with [uv](https://docs.astral.sh/uv/):

```sh
uv sync
uv run python experiments/129_outside_relief.py --help
```

Most scripts take `--help`, and all write to `outputs/`. Several take hours; the
outputs they produced are already in `outputs/`, so the tables can be rebuilt
without re-running the searches.

`uv run pytest` runs the unit tests; all 159 pass.

## Which script wrote which result

[`outputs/MANIFEST.md`](outputs/MANIFEST.md) indexes all 229 result files: what
wrote each one, what reads it, and the run configuration the file itself records
in its own columns. It is generated by `tools/build_manifest.py`, so it can be
rebuilt after any new run:

```sh
uv run python tools/build_manifest.py
```

205 of the 229 are attributed, and every attribution states the evidence it rests
on. Most are read straight out of the source. The rest come from the console logs
of the original runs, kept in [`outputs/logs/`](outputs/logs/) and fingerprinted
against the prose each script prints; where that evidence overlaps the source, the
two agree on 47 of 48 files.

The remaining **24 are marked unattributed rather than guessed at**. Those were
written by passing `--out <name>` on the command line, under names this repository
records nowhere and no run log covers. Their configuration column is still exact —
it is read out of the file — and the manifest names any figure or table script that
consumes them. If you re-run an experiment, prefer its `--out` default, or keep the
console log, so the result stays attributable.

## Feeder data is not included, and where to get it

Every feeder is third party and publicly obtainable. None is redistributed here,
so `data/opendss/` and `cache/` are absent and must be populated before any script
that touches a feeder will run.

| Feeder | Source | Expected location |
|---|---|---|
| Swiss 55-node MV | EPFL DESL, <https://github.com/DESL-EPFL/55nodes-Swiss-distribution-grid> | pass the `.mat` file with `--mat` |
| SMART-DS `uhs2_1247--udt10746` | `s3://oedi-data-lake/SMART-DS/v1.0/2018/GSO/urban-suburban/scenarios/base_timeseries/opendss_no_loadshapes/uhs2_1247/` (anonymous, `--no-sign-request`) | `cache/smartds/` |
| EPRI Ckt7, Ckt24 | EPRI "Green Circuits" distribution feeder set | `data/opendss/ckt7/Master_ckt7.dss`, `data/opendss/ckt24/master_ckt24.dss` |
| ENWL LV networks | Electricity North West, Low Voltage Network Solutions; models and the companion `LCTProfiles` archive are separate downloads | `cache/enwl/`, `cache/enwl_full/<network>/<feeder>/` |
| IEEE European LV | dss-extensions `electricdss-tst` LVTestCase | `data/opendss/eulv/` |

One non-feeder input **does** ship, in `data/interconnection/`: the empirical
request-size distribution behind Appendix A and experiments 71/73, derived from
the **California DG Stats Interconnected Applications** data set (CPUC Decision
14-11-001). It is a summary of a public data set rather than a redistributed
grid model; `data/interconnection/PROVENANCE.md` gives the source, the exact
export used, and the scope limits.

`.env.default` lists the one API key an experiment still needs — `ENWL_KEY`, for
the ENWL open-data portal query in `27_enwl_capacity_register_check.py`. None of
the results in this paper requires it.

## Not included

Internal planning documents, referee correspondence and venue-decision memos are
withheld, as are this project's other research lines: the OpenStreetMap →
pandapower model-synthesis toolkit and its conductor-assignment benchmark, and
the planning notes for a separate paper on arrival-order pricing. Cross-
references to all of these survive in script docstrings and in the milestone
bars quoted throughout `docs/joint-allocation-scope.md`; they will not resolve.
The 2.1 GB solver cache is also omitted; it is regenerated on demand.
